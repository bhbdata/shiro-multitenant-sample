# Wonders — 对话整理技能

## 概述

把一次对话交流沉淀为一篇结构化、可重温的 Markdown 笔记。本质不是「复制聊天记录」，而是通过归纳、提炼与延伸，让对话产生**知识增量**——既保留核心脉络，又补充思考深度与文献支撑。

## 触发条件

在以下任一情况执行本技能：

- 用户消息包含关键词 **wonders**（大小写不敏感）
- 用户显式调用 **/wonders**

若对话过短、无实质讨论、或用户仅做简单查询，应礼貌说明无需沉淀，不生成文件。

## 你的工作方式

### Phase 1：回溯与提炼

1. 回顾当前对话的全部轮次，识别：
   - **用户真正想解决的问题是什么**（往往藏在表述背后，需要你替用户点破）
   - 讨论中达成的关键共识、分歧、未决点
   - 讨论涉及的领域、概念、人名、文献线索
2. 不做逐字摘录，而是先在脑中（或草稿中）完成「从对话到要点」的归纳。

### Phase 2：按三部分结构撰写

始终使用以下模板生成 Markdown 内容（格式约束，需严格遵守结构，措辞可灵活）：

```markdown
# [YYYY-MM-DD] [话题简短概括]

## 一、总结与澄清

[澄清本次讨论的核心内容、本质上想问/想解决的是什么问题。
点破用户可能未明说的真实意图。1-3 段，简洁。]

## 二、归纳总结

[对我们讨论内容的提炼与梳理——不是复制聊天记录，而是归纳要点。
用分点或小标题组织，体现逻辑层次。覆盖关键结论、方法、分歧。]

## 三、延伸补充

### 思考延伸

[基于讨论主题的拓展思考，可联系相关理论、思想传统、概念框架。
这是给对话「加深度」的部分。]

### 相关文献

[可引用的著作、论文、思想家，附简短说明其关联。
若无可靠来源，宁可注明「待补充」也不要编造引用。]
```

### Phase 3：保存文件

1. 将生成的笔记写入项目目录 **`wonders/`**（若不存在则创建）。
2. 文件名格式：`YYYY-MM-DD-<话题简短概括>.md`
   - 使用 ASCII 连字符分隔词语；中文话题可直接用于文件名。
   - 示例：`wonders/2026-07-09-大模型哲学流派对比.md`
3. 写入完成后，向用户简要说明：文件路径、话题概括、以及笔记中补充了哪些延伸内容。

## 质量要求

- **归纳优先**：第二部分必须是提炼后的知识结构，不是对话流水账。
- **诚实引用**：文献部分只列有把握的来源；不确定时写「待补充」。
- **意图澄清**：第一部分应点破用户未明说的真实关切，这是本技能的核心价值。
- **篇幅适中**：整篇笔记宜控制在可读范围内；复杂话题用层级标题组织，避免堆砌。

## 不适用场景

- 单轮简单问答（如「这个 API 怎么用」且无延伸讨论）
- 纯操作指令、代码修复任务（无知识性讨论需沉淀）
- 用户明确表示不需要保存或整理
